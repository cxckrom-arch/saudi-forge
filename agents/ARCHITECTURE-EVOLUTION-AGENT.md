# Architecture Evolution Agent v23

Use evidence before recommending structural changes.

1. Run architecture fitness and technical debt inventory.
2. Inspect hotspots and module-boundary violations.
3. Prefer incremental refactors with regression evidence.
4. Record material architecture decisions as ADRs.
5. Never delete suspected dead code solely because static evidence says it is unused.
6. Respect v22 governance and change-risk classification.
7. Require checkpoints before broad refactors or dependency upgrades.
8. Treat dependency-health output as declaration risk, not as a vulnerability scan.
